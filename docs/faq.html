# Frequently Asked Questions ## General Questions ### Q: What is DevToolBox? **A:** DevToolBox is a hybrid web-based application suite of development tools designed specifically for data plane developers and software engineers. It includes tools for PCAP analysis, file manipulation, and more. ### Q: Is it free? **A:** Yes! DevToolBox is open source under the MIT License and completely free. ### Q: Do I need to install anything to use it? **A:** The frontend is web-based, so you only need a modern browser. However, the backend requires Python 3.8+ and Node.js. ## PCAP Editor Questions ### Q: What file formats are supported? **A:** PCAP and PCAPNG formats are fully supported. ### Q: What's the maximum file size? **A:** Currently, the maximum file size is 100 MB per upload. You can modify this in the backend configuration. ### Q: Can I modify packets after uploading? **A:** Yes! You can edit the payload of any packet and the tool will automatically recalculate checksums. ### Q: What protocols are supported? **A:** IPv4, IPv6, TCP, UDP, ICMP, and any protocols encapsulated in these are supported. ### Q: Can I create packets from scratch? **A:** This is a planned feature. Currently, you can only modify existing packets from uploaded files. ## Setup & Deployment ### Q: How do I set up DevToolBox locally? **A:** Follow the Installation Guide in the documentation: 1. Clone the repository 2. Set up Python virtual environment 3. Install backend dependencies 4. Run Flask server 5. Install frontend dependencies 6. Run dev server ### Q: Can I run it in Docker? **A:** Yes! A Dockerfile is provided. Use `docker build` and `docker run`. ### Q: How do I deploy to production? **A:** Options include: - GitHub Pages for static frontend - Cloud platforms (AWS, Heroku, DigitalOcean) for backend - Docker containers for easy deployment ### Q: Is HTTPS supported? **A:** The development server uses HTTP. For production, use a reverse proxy (nginx, Apache) with SSL certificates. ## Performance & Limitations ### Q: Why is it slow with large files? **A:** Large PCAP files require more processing time. Consider: - Filtering the PCAP before uploading - Increasing server resources - Using the API directly for batch processing ### Q: Can I process files larger than 100 MB? **A:** The limit is configurable. Modify `MAX_FILE_SIZE` in `backend/app.py`. ### Q: Does it support concurrent uploads? **A:** Yes, the Flask server can handle multiple concurrent requests. ## Technical Questions ### Q: What's the difference between PCAP and PCAPNG? **A:** - **PCAP:** Traditional libpcap format, widely supported - **PCAPNG:** Newer format with more metadata and options DevToolBox handles both transparently. ### Q: How are checksums recalculated? **A:** When you modify a packet, the tool automatically: 1. Recalculates IP header checksum 2. Recalculates TCP/UDP checksum 3. Rebuilds the packet with new checksums ### Q: Can I use the backend API directly? **A:** Yes! The API is fully documented. You can use it with any HTTP client (curl, Postman, Python requests, etc.). ### Q: Is there a command-line interface? **A:** Currently, there's only a web interface. CLI tools may be added in the future. ## Contributing & Development ### Q: How can I contribute? **A:** Check the Contributing Guide for: - How to fork and submit PRs - Code standards - How to add new tools ### Q: Can I add my own tools? **A:** Yes! The architecture is designed to be extensible. Follow the guidelines for adding new tools. ### Q: What's the roadmap? **A:** Planned features include: - File Merger tool - Hex Viewer - Log Analyzer - Performance Analyzer - User authentication - Real-time collaboration ## Troubleshooting ### Q: I get a CORS error **A:** Ensure the frontend can reach the backend. Check: - Backend is running on port 5000 - Frontend proxy is configured correctly - CORS is enabled in Flask ### Q: File upload fails **A:** Verify: - File is a valid PCAP/PCAPNG - File is under 100 MB - Check browser console for error messages ### Q: Packets won't modify **A:** Ensure: - Hex payload is valid (even length, 0-9 A-F only) - Packet has a payload to modify - Check server logs for errors ### Q: Port 5000/8080 already in use **A:** Change the port in: - Backend: `app.py` - `app.run(port=5001)` - Frontend: `vite.config.js` - `server: { port: 8081 }` ## Support & Resources ### Where can I get help? - Check the documentation at `/docs` - Open an issue on GitHub - Read the API reference for integration help ### Is there a community? Yes! Join discussions on GitHub and contribute to the project. ### How do I report bugs? Open a GitHub issue with: - Clear description - Steps to reproduce - Your environment details - Screenshots if applicable ## Security Questions ### Q: Is my data secure? **A:** Files are processed locally on your server. Data doesn't leave your machine unless you explicitly download and share it. ### Q: Do you collect any data? **A:** No! DevToolBox is self-hosted and doesn't send data anywhere. ### Q: Should I use this in production? **A:** The tool is suitable for development and testing. For critical production environments: - Run on secure networks - Implement authentication - Use HTTPS - Regular backups of PCAP files ## License Questions ### Q: What license is DevToolBox under? **A:** MIT License - permissive open source license. ### Q: Can I use it commercially? **A:** Yes, the MIT License allows commercial use. ### Q: Do I need to attribute DevToolBox? **A:** Attribution is appreciated but not required by the MIT License. --- ## Still Have Questions? 1.
